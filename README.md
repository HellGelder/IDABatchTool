# IDA Batch Tool

Кроссплатформенный инструмент для пакетного анализа бинарных файлов с использованием IDA Pro, Hex‑Rays и BinDiff.

* **Пакетный анализ** — параллельный запуск нескольких копий IDA.
* **Автоматический экспорт** — дизассемблер, псевдокод, метаданные в JSON.
* **HTML‑отчёты в стиле Apple** — интерактивные отчёты с групповым списком категорий, drill‑down до модулей, быстрым поиском, подробными тултипами метрик и прогресс-барами.
* **Сравнение директорий** — два движка на выбор: **BinDiff** и **Diaphora** (по отдельности или вместе).
* **Анализ системных функций (СФ)** — документация API с учётом целевой платформы: Windows (MS Learn), Linux/Android (man-pages), macOS/iOS.
* **Поддержка архивов** — автоматическая распаковка APK, IPA, DMG.
* **Графический интерфейс** — современный UI на PySide6.
* **CLI** — возможность запуска из командной строки для автоматизации.

# Установка

```bash
git clone https://github.com/<your-org>/IDABatchTool.git
cd IDABatchTool
pip install -r requirements.txt
```

Файл `requirements.txt` содержит минимальные версии зависимостей:

```

lxml>=4.9              # бэкенд bs4 и разбор XML
```

## 2. IDA Pro 9.x

Установите IDA Pro версии **9.0 или выше**. Инструмент использует текстовый интерфейс IDA (`idat` / `idat.exe`) в пакетном режиме — GUI не требуется.

После установки убедитесь, что `idat` доступен одним из способов:
- Прописан в системном `PATH`
- Указан абсолютный путь в `config.yaml` (ключ `ida.executable`)
- Находится в типичной папке установки:
  - Windows: `C:\Program Files\IDA Professional 9.x\idat.exe`
  - Linux: `~/ida-pro-9.0/idat` или `/opt/ida-pro-9.0/idat`
  - macOS: `/Applications/IDA Professional 9.x.app/Contents/MacOS/idat`

Инструмент автоматически ищет IDA в этих путях, если в конфиге указано просто `idat`.

## 3. Плагин BinExport 12

**Обязателен.** Используется для экспорта баз `.i64` в формат `.BinExport`, необходимый для сравнения в BinDiff.

1. Скачайте [BinExport 12](https://github.com/google/binexport/releases/tag/v12) для вашей ОС и архитектуры IDA.
2. Скопируйте файл плагина в папку `plugins` вашей установки IDA Pro:
   - Windows: `C:\Program Files\IDA Professional 9.x\plugins\binexport12_ida64.dll`
   - Linux: `~/ida-pro-9.0/plugins/binexport12_ida64.so`
   - macOS: `~/ida-pro-9.0/plugins/binexport12_ida64.dylib`
3. При запуске IDA в консоли убедитесь, что плагин загружается:
   ```
   BinExport 12 (@6447866, Mar  2 2026), (c)2004-2011 zynamics GmbH, (c)2011-2025 Google LLC.
   ```

**Важно:** Инструмент вызывает BinExport через headless-флаг IDA: `-OBinExportAutoAction:BinExportBinary`. Плагин должен поддерживать `AutoAction` — BinExport 12 поддерживает.

## 4. BinDiff 8 (standalone CLI)

**Обязателен для сравнения движком BinDiff.** Используется standalone-версия `bindiff` (командная строка), **не** IDA-плагин.

> **Почему standalone, а не плагин?**
>
> Плагин BinDiff для IDA (`bindiff8_ida64`) предназначен для интерактивной работы в GUI. Формально он экспортирует символ `PLUGIN` и даже регистрирует IDC-функцию `BinDiffDatabase('secondary_idb', 'results_file')`, но эта функция **игнорирует переданные аргументы** и вызывает внутренний `ExportIdbs()`, который открывает интерактивный диалог выбора вторичной базы (`GetOpenFilename`) и требует, чтобы primary-база была уже открыта в текущем экземпляре IDA. В headless-режиме (`idat -A`) такой диалог блокирует процесс. Python-API у плагина нет.
>
> Для пакетной обработки Google предоставляет отдельный CLI `bindiff.exe` / `bindiff`, который и используется в проекте. Это документированный путь для автоматизации.

Справочная информация о CLI (`bindiff --help`):

| Флаг | Назначение |
|------|------------|
| `--primary`, `--secondary` | пара входных `.BinExport` (файлы или позиционные аргументы) |
| `--output_dir` | каталог для результата (по умолчанию — текущий) |
| `--output_format` | `bin` (SQLite-база `.BinDiff`, по умолчанию), `log` (текстовый `.results`), `none` |
| `--config` | путь к конфиг-файлу (стратегии матчинга и пороги) |
| `--export` | пакетный экспорт `.idb`/`.i64` из каталога в `.BinExport` |
| `--ls` | вывести хэши и имена всех `.BinExport` в каталоге |
| `--md_index` | дамп MD-индексов без сравнения |
| `--print_config` | вывести разобранную конфигурацию (JSON) и выйти |
| `--ui` | запустить интерактивный Java-UI (требует JRE) |
| `--logo` | вывод версии и copyright |

Инструмент парсит результат в SQLite-базу `.BinDiff` (таблицы `metadata`, `file`, `function`, `basicblock`, `instruction`, `functionalgorithm`, `basicblockalgorithm`) и построчный текст `.results`. Структурированного JSON-вывода у BinDiff нет — его формирует сам проект.

### Windows

1. Скачайте [bindiff_8_amd64.msi](https://github.com/google/bindiff/releases/tag/v8).
2. Установите MSI, следуя инструкциям.
3. Убедитесь, что `bindiff.exe` доступен из `PATH`, или положите его в корень проекта, или укажите полный путь в `config.yaml` (ключ `bindiff.executable`).

> **Примечание:** `bindiff.exe` (~3.8 МБ) сейчас присутствует и в репозитории, и в рабочем каталоге. В `.gitignore` он указан, но это на файл не действует, пока он остаётся в индексе git. Если вы не хотите хранить бинарник в истории — удалите его из индекса (`git rm --cached bindiff.exe`) и ставьте BinDiff через MSI.

### Linux (Debian/Ubuntu)

```bash
wget https://github.com/google/bindiff/releases/download/v8/bindiff_8_amd64.deb
sudo dpkg -i bindiff_8_amd64.deb
# Если возникнут проблемы с зависимостями:
sudo apt --fix-broken install
```

### macOS

```bash
brew install --cask bindiff
# или скачайте .dmg с https://github.com/google/bindiff/releases/tag/v8
```

После установки `bindiff` должен быть доступен в терминале:
```bash
bindiff --help
```

## 5. Плагин BinDiff 8 (опционально, для GUI IDA)

Если вы также хотите использовать BinDiff **интерактивно** внутри IDA Pro (вне данного инструмента) — например, вручную править совпадения или переносить символы и комментарии, — установите плагин:

1. Скачайте и установите BinDiff 8 (тот же установщик, что и для CLI).
2. При установке выберите интеграцию с IDA Pro.
3. Файлы плагина (`bindiff8_ida64.dll` и др.) будут помещены в per-user каталог плагинов IDA (`%APPDATA%\Hex-Rays\IDA Pro\plugins\bindiff\`).

На работу данного инструмента это не влияет — он всегда использует standalone CLI.

## Страницы

1. **Анализ** — выбор директории, автоопределение платформы по расширениям, настройка флагов анализа, прогресс-бар и Treemap статуса файлов.
   - После завершения анализа доступна кнопка «Сгенерировать HTML-отчёты».
   - Флаги: удаление `.asm`/`.log`, удаление временных файлов IDA (`.id0`, `.id1`, `.nam`, `.til`), включение псевдокода в JSON, удаление JSON после генерации отчётов.
   - Поддерживается доанализ: если часть файлов уже имеет `.i64`, можно доанализировать новые, перезаписать всё или только экспортировать существующие.

2. **Сравнение (Diff)** — выбор левой (эталонной) и правой (текущей) папок с `.i64`, автоматическое сопоставление по именам, запуск сравнения и генерация отчётов.
   - **Движок сравнения** выбирается переключателем: **только BinDiff**, **только Diaphora** или **оба** (результаты объединяются, приоритет совпадений `both` → `bindiff` → `diaphora`).
   - Для колонок статусов в таблице пар отдельно отображается прогресс BinDiff и Diaphora.

3. **Анализ СФ** — анализ системных функций с учётом **выбранной целевой платформы**:
   - Windows — документация через Microsoft Learn CLI (`npx`);
   - Linux / Android — офлайн-база man-pages;
   - macOS / iOS — встроенный классификатор.
   - Платформа определяется автоматически по расширениям файлов, но её можно задать вручную.

4. **Конфигурация** — пути к IDA и BinDiff, проверка вспомогательных утилит (7z, npx), загрузка базы man-pages, тема оформления.

Поддерживаются светлая (`light`) и тёмная (`dark`) темы, переключаемые на странице «Конфигурация». HTML-отчёты всегда генерируются в светлой теме (Apple-стиль).

# HTML-отчёты

HTML-отчёты спроектированы в духе Apple Human Interface Guidelines:

- **Сводный отчёт анализа** (`IDAReports/index.html`) — hero-карточка с общей информацией, плитки статистики, **интерактивный список категорий импортированных модулей с drill-down** в правую панель, список секций ELF, перечень исследованных файлов со ссылками.
- **Индивидуальный отчёт** (`*.html`) — sticky-заголовок, поиск по функциям/импортам/экспортам, аккордеоны с зависимостями (цветные маркеры, grid-сетка), таблицы импортов и экспортов, дизассемблированные функции с hex-дампом и псевдокодом.
- **Сводка сравнения** (`DiffResults/Reports/index.html`) — статистика по парам, таблица с tinted-бейджами схожести (зелёный >80%, жёлтый 50-80%, красный <50%), статусами хэшей.
- **Отчёт сравнения пары** (`*.html`) — прогресс-бары схожести/уверенности, grouped lists статистики по каждому файлу, таблица совпавших функций с тултипами методики.
- **Сводка СФ** (`SFAReports/index.html`) — плитки статистики и список отчётов.
- **Детальный СФ** (`*.sfa.html`) — split-view: sidebar со списком системных вызовов + интерактивная панель с параметрами и вкладками документации (Markdown).

Таблицы функций, импортов и совпадений используют **DataTables** (поиск, сортировка, пагинация) с корректным числовым порядком сортировки.

Все отчёты полностью автономны (offline): JavaScript-зависимости вендорятся локально в `ida_batch_tool/reporting/templates/vendor/` (`marked.min.js` для Markdown, `datatables.min.js` / `datatables.min.css` для таблиц) и инлайнятся в HTML при генерации.

# Сравнение директорий (BinDiff и Diaphora)

Страница «Сравнение» позволяет сопоставить две версии одного приложения, используя один из двух движков или оба одновременно.

## Движки сравнения

| Движок | Как работает | Результат |
|--------|--------------|-----------|
| **BinDiff** | экспорт `.i64` → `.BinExport` (headless IDA), затем `bindiff --primary … --secondary …` | SQLite-база `.BinDiff` |
| **Diaphora** | экспорт баз через bundled-скрипты (`scripts/diaphora`), затем сравнение | SQLite-база Diaphora |

При выборе «оба» результаты объединяются: для одной и той же пары функций приоритет отдаётся совпадению с источником `both`, затем `bindiff`, затем `diaphora`.

## Принцип работы (движок BinDiff)

1. **Экспорт через плагин BinExport (headless IDA)**:
   ```
   idat -A -OBinExportAutoAction:BinExportBinary -OBinExportModule:<output.BinExport> <file.i64>
   ```
   Плагин BinExport поддерживает `AutoAction` — выполняет экспорт и завершает IDA автоматически без GUI.

2. **Сравнение через standalone bindiff CLI**:
   ```
   bindiff --primary <file1.BinExport> --secondary <file2.BinExport> --output_dir <tmp>
   ```
   Результат — SQLite-база `.BinDiff` (для её разбора CLI требует корректно завершиться с кодом 0; вспомогательный каталог `*_tmp` затем удаляется).

3. **Парсинг** `.BinDiff` → `.diff.json` с метаданными, совпавшими функциями и метриками (уровни схожести, алгоритмы матчинга, распределение по buckets).

4. **Генерация HTML-отчётов** с прогресс-барами, таблицами и тултипами методики.

Дополнительно для пар с низкой схожестью (BinDiff < 99%) можно запустить **доанализ Diaphora** в каталог `AddDiffResults/` — совпадения оттуда подмешиваются к результатам BinDiff.

## Пошаговая инструкция

1. Выберите **движок сравнения** (BinDiff / Diaphora / оба).
2. Укажите левую (эталонную) и правую (текущую) папки с базами `.i64`.
3. Виджет сопоставления покажет, зеркальные ли директории, и выделит отсутствующие файлы.
4. Нажмите «Запустить сравнение» — в фоновом потоке выполнится экспорт + сравнение для каждой пары.
5. После завершения нажмите «Сгенерировать HTML-отчёт» — в папке `DiffResults/Reports` появится индексный файл со сводной статистикой и ссылками на детальные отчёты.

## Метрики сравнения

| Метрика | Описание |
|---------|----------|
| **Схожесть (Similarity)** | 0–1. Структурная близость файлов. Формула: ~35% рёбра потока управления, ~25% базовые блоки, ~10% функции, ~10% инструкции, ~20% разница MD-индекса графа вызовов |
| **Уверенность (Confidence)** | 0–1. Надёжность найденного соответствия. Среднее качество алгоритмов, сглаженное сигмоидой |
| **Базовые блоки** | Последовательности инструкций с одной точкой входа и выхода — минимальные единицы сравнения |
| **Инструкции** | Сравниваются по мнемоникам (операнды игнорируются — адреса и константы могут меняться) |
| **Рёбра CFG** | Связи между базовыми блоками в графе потока управления |

# Анализ системных функций (СФ)

Страница «Анализ СФ» документирует вызовы API в бинарных файлах с учётом **целевой платформы**.

1. Выберите **целевую платформу** (Windows / Linux-Android / macOS-iOS). Платформа определяется автоматически по расширениям файлов, но её можно задать вручную.
2. Укажите директорию с бинарными файлами (аналогично странице «Анализ»).
3. Нажмите «Запустить анализ СФ» — выполнится экспорт в JSON (как на странице «Анализ»).
4. Нажмите «Сгенерировать HTML-отчёт СФ».

Источники документации зависят от платформы:

| Платформа | Источник документации |
|-----------|----------------------|
| **Windows** | Microsoft Learn CLI: `npx @microsoft/learn-cli search <function>`. Результаты кэшируются в `mslearn_cache.db`. При первом запуске инструмент предложит синхронизировать базу сигнатур Win32 API (`win32api.db`). |
| **Linux / Android** | Офлайн-база man-pages (`manpages.db`). Загружается кнопкой «Скачать и импортировать» на странице «Конфигурация» (официальный tarball man-pages → парсинг roff → SQLite). Путь задаётся ключом `manpages_db_path`; если не задан — база ищется рядом с результатами (`SFAReports/manpages.db`). |
| **macOS / iOS** | Встроенный классификатор системных модулей; внешняя документация не требуется. |

Для Linux/Android счётчики отчёта разделяют импорты и системные библиотеки (по выбранной ОС), а для Windows дополнительно учитываются системные DLL-фильтры.

# Работа с архивами

Инструмент умеет извлекать исполняемые файлы из:

- **APK** (Android) — библиотеки `.so` из `lib/`
- **IPA** (iOS) — исполняемый файл приложения из `Payload/*.app/`
- **DMG** (macOS) — содержимое образа (требуется `7z`)

Достаточно положить архив в анализируемую папку. Архив будет автоматически распакован в соседнюю папку с тем же именем, и все исполняемые файлы внутри него добавятся в очередь анализа. Повторная распаковка не производится — если папка уже существует, она используется как есть.

Файл `config.yaml` в корне проекта управляет настройками. При первом запуске создайте его из примера:

```bash
cp config.yaml.example config.yaml
```

Содержимое `config.yaml.example`:

```yaml
# Путь к исполняемому файлу IDA Pro 9.0+ (idat).

  executable: bindiff

# Максимальное количество параллельных экземпляров IDA.
max_ida: 4

# Уровень логирования: DEBUG / INFO / WARNING / ERROR.
log_level: INFO

# Тема интерфейса: light / dark.
theme: light

# Путь к папке хранения локальных БД сигнатур (например, win32api.db).
```

# FAQ

### Почему используется standalone bindiff.exe, а не плагин BinDiff для IDA?

Плагин BinDiff для IDA (`bindiff8_ida64`) — GUI-инструмент. Он имеет ровно одну скриптовую точку входа — IDC-функцию `BinDiffDatabase('secondary_idb', 'results_file')`, — но она **игнорирует оба аргумента** и вызывает внутренний `ExportIdbs()`, который открывает интерактивный диалог выбора вторичной базы (`GetOpenFilename`) и требует, чтобы primary-база была открыта в текущем экземпляре IDA. В headless-режиме (`idat -A`) диалог блокирует процесс, а Python-API у плагина отсутствует. Для автоматизированного пайплайна используется standalone CLI `bindiff`, который принимает пути `--primary`/`--secondary` и выдаёт машиночитаемую SQLite-базу `.BinDiff`.

### Почему HTML-отчёты не поддерживают тёмную тему?

Отчёты используют единый CSS-partial с Apple-палитрой (светлая). Тёмная тема для отчётов не реализована, так как они предназначены для чтения и архивации. GUI поддерживает обе темы.

### Можно ли анализировать файлы без интернета?

В основном да. Все зависимости HTML-отчётов (`marked.min.js`, `datatables.min.js` / `datatables.min.css`) вендорены локально в `templates/vendor/` и инлайнятся в отчёты. Документация для Linux/Android берётся из офлайн-базы `manpages.db` (загружается один раз), для macOS/iOS — из встроенного классификатора. Интернет требуется только для:
- поиска документации Windows-функций через `npx @microsoft/learn-cli search` (результаты кэшируются в `mslearn_cache.db`);
- разовой синхронизации базы сигнатур Win32 API (`win32api.db`) и загрузки архива man-pages.

### Чем отличаются движки сравнения BinDiff и Diaphora?

**BinDiff** — движок от Google/zynamics (open source, Apache 2.0) на основе структурной сигнатуры графов; даёт similarity/confidence и методику матчинга. **Diaphora** — независимый открытый движок с собственными эвристиками (AGPL-3.0); поставляется в репозитории (`scripts/diaphora`) и не требует отдельной установки. Их можно запускать по отдельности или вместе — во втором случае совпадения объединяются с приоритетом `both` → `bindiff` → `diaphora`.

### Как добавить поддержку новой платформы в классификатор?

Добавьте словарь модулей (как в `classifier/android.py`) и зарегистрируйте его в `classifier/platform_classifier.py`. Формат: `{ "имя_модуля": "описание на русском" }`.
